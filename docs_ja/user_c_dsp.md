# C でオーディオエフェクトとオシレータを書く

Tulip と AMYboard では、**C で書いたオーディオ DSP を、Python から、実行時に**動かせます。`tulip.install_c_process()` に C コードの文字列を渡すと、しばらくして AMY のオーディオエンジンの内部でコンパイルされ、実行されます。実機の上で、ツールチェーンも再起動も再書き込みも不要です。文字列を編集して再度インストールすれば、動作中のコードをホットスワップできます。

これは Tulip が動くすべての環境で使えます。

| プラットフォーム | 内部で使うコンパイラ |
| -------- | ------------------- |
| Tulip CC / AMYboard（ESP32-S3） | `xcc700`、オンデバイスの小さな C コンパイラ |
| Tulip Desktop（macOS） | `libtcc` によるインメモリ JIT |
| Tulip Web / AMYboard Web | 同じく `xcc700`。AMY の AudioWorklet に WebAssembly を出力 |

Python API と、書く C のコードはどの環境でも同じです。このガイドのサンプルを収めた実行可能なデモが `/sys/ex/c_dsp_demo.py` に同梱されています。（実装の詳細は[設計ドキュメント](user_c_dsp_design.md)を参照してください。）

## クイックスタート: 6 行のビットクラッシャー

```python
import tulip

tulip.install_c_process('crush', """
    int i = 0;
    while (i < frames * chans) {
        buf[i] = (buf[i] >> 18) << 18;   // 小数部の上位 5 ビットだけ残す
        i = i + 1;
    }
""")
tulip.c_process('crush', True)   # バス 0 で有効化 -- 以降に鳴らす音はすべてクラッシュされる
```

何か音を鳴らしてみてください。十分堪能したら:

```python
tulip.c_process('crush', False)
```

Tulip に渡したのは C 関数の**本体**だけです。シグネチャとヘルパーの宣言は自動的に周りに付けられます。文字列を編集して（`>> 20` を試してみてください）もう一度 `install_c_process` を呼べば、新しいコードが古いものをその場で置き換えます。バスの割り当てはそのままで、音は途切れません。

## API

| 呼び出し | 内容 |
| ---- | ------------ |
| `tulip.install_c_process(name, src)` | `src` を**エフェクト**としてコンパイルし、`name` の下にインストールします。スロット番号を返し、コンパイルできない場合はコンパイラのメッセージ付きで `ValueError` を送出します。 |
| `tulip.install_c_osc(name, src)` | 同じですが、**オシレータ**としてインストールします。 |
| `tulip.c_process(name, on, bus=0)` | バス（0〜3）上でエフェクトを有効／無効にします。1 つのエフェクトを複数のバスで同時に動かせます。 |
| `tulip.c_osc(name, osc, on=True)` | AMY のオシレータ番号 `osc` を自作オシレータに向けます（あるいは解除します）。複数の osc が 1 つのインストール済みプログラムを鳴らせます。 |
| `tulip.c_process_calls(name)` | インストール以降にコードが処理したオーディオブロック数。「本当に動いているか」を最短で確認する手段です。 |
| `tulip.uninstall_c_process(name)` | （どちらの種類でも）削除し、コンパイル済みコードを解放します。 |

スロットは 8 つあり、エフェクトとオシレータで共有します。既存の名前で再インストールするとそのスロットを再利用し、バスの有効化状態や osc のバインドを維持します。つまり編集と試聴のループは「文字列を編集 → インストール → 聴く」だけです。

## サンプル形式と、常に使えるヘルパー

サンプルは AMY のネイティブな固定小数点、**S8.23 の `int`** です。1.0 は `1 << 23`（8388608）にあたります。float はありません。高速な浮動小数点演算を持たないマシンで動かすためであり、固定小数点で考えること自体が楽しみの一部でもあります。次の 4 つのヘルパーは常にスコープ内にあります。

| ヘルパー | 意味 |
| ------ | ------- |
| `fxmul(a, b)` | S8.23 の 2 数を掛けます（1.0 == `1<<23` としての `a*b`）。 |
| `cos_lut(phase)` | AMY のコサインテーブル。`phase` は 1 周期に正規化された S8.23（0 〜 `1<<23`）で、-1.0〜1.0 の S8.23 を返します。 |
| `to_int16(s)` | S8.23 → おなじみの 16 ビット PCM（-32767〜32767）、クランプ付き。 |
| `from_int16(v)` | 16 ビット PCM → S8.23。 |

トラッカーのように 16 ビットサンプルで考えたければ、入出力時に変換してください: `buf[i] = from_int16(my_math(to_int16(buf[i])));`

## エフェクト

エフェクトの本体からは次のシグネチャが見えます。

```c
void process(int *buf, int frames, int chans)
```

`buf` は、AMY 自身の FX チェーン（EQ、コーラス、エコー、リバーブ）を**通過したあと**のライブなバスバッファです。つまり、あなたはスピーカーの直前にいます。バッファは、`frames` サンプルからなるチャンネルブロックが `chans` 個、連続して並んだ形です（インターリーブではありません）。左は `buf[0]` 〜 `buf[frames-1]`、右は `buf[frames]` から始まります。その場で書き換えてください。バスでの有効化は `tulip.c_process(name, True, bus)` で行います。

## オシレータ

オシレータの本体からは次のシグネチャが見えます。

```c
void render(int *buf, int frames, int osc,
            int phase_inc_q16, int amp)
```

`buf`（モノラル）を `frames` サンプル分埋めてください。その後 AMY が osc のパンを適用し、他のオシレータと同じようにミックスします。ブロックごとに 2 つの音楽的な入力が得られます。

- `phase_inc_q16` — そのノートの**現在のピッチ**に対応する、サンプルあたりの位相ステップ。65536 が 1 周期を意味します。ピッチベンドやポルタメントにリアルタイムで追随します。
- `amp` — 今この瞬間のエンベロープレベル、S8.23。出力をこれで `fxmul` すれば、オシレータが AMY の ADSR に従います。

AMY の osc にバインドすれば、他のオシレータと同じように演奏できます。

```python
tulip.install_c_osc('mine', SRC)
tulip.c_osc('mine', 200)
amy.send(osc=200, wave=amy.SINE, bp0='10,1,500,0.2,250,0', vel=0)
amy.send(osc=200, note=60, vel=1)
```

**大きい osc 番号を使ってください（200 番台を習慣にするとよいでしょう）。** 若い番号のオシレータはデフォルトの MIDI シンセのものなので、制御を奪い合うことになります。シンセが所有する osc に送ったイベントは無音になります。

ポリフォニー: 複数の osc を同じ名前にバインドし、`osc` 引数でインデックスする static 配列に osc ごとの状態を持たせてください（後述の CZ の例を参照）。

## 呼び出しをまたいで状態を保持する

本体の中で変数を `static` として宣言すると、インストールされている間ずっと生き続けます。フィルタが記憶を保ち、オシレータが位相を保ち、ディレイがバッファを保つのはこの仕組みです。

```c
static int last;                       // 永続する int 1 つ
static int phase[256];                 // osc ごとの状態、`osc` でインデックス
static int16_t delayline[22050];       // 16 ビットモノラルで 0.5 秒分
```

（再）インストール時にはすべてゼロから始まります。

## 書ける C の範囲

Tulip Desktop ではコンパイラはフル機能の C の JIT（`libtcc`）で、include も float も struct も何でも使えます。Tulip CC、AMYboard、ウェブビルドでは意図的に小さくした C である `xcc700` です。

- `int` と `int16_t`、およびそれらのポインタと配列。`enum`、`static`
- `while`、`if`/`else`、`return`。関数（`process`/`render` の上にヘルパーを定義して呼び出せます）
- 整数式の演算子一式: `* / % + - << >> < <= > >= == != & ^ |` `&& || ! ~`、代入
- float、struct、`for`、プリプロセッサ（`#define` など）は**使えません**

このサブセットの範囲で書けば、同じ文字列がすべてのプラットフォームで動きます。（式の挙動がおかしいと感じたら、括弧を足してみてください。そのうえで演算子の優先順位についての思い込みを疑ってみましょう。）

守られることが保証された警告が 2 つあります。

- **シンセをクラッシュさせられます。** これはオーディオ経路上で動く本物のマシンコードです。バッファの外に書き込んだり、ゼロ除算したりすると、シンセ全体が止まります（ハードウェアでは再起動します）。それも楽しみのうちですが、作業内容は保存しておきましょう。
- **速く保ちましょう。** コードはオーディオスレッド上で、バスごと（あるいは鳴っている osc ごと）にブロック 1 回につき 1 度実行されます。整数演算は安価ですが、巨大なループはそうではありません。

## 例: ビットクラッシャー（エフェクト）

先ほどのクイックスタートの内容です。右シフトしてから左シフトすると下位ビットが捨てられ、波形がざらついた段差に量子化されます。深さを変えながらライブで試してみてください。インストールのたびに直前のものとホットスワップされます。

```python
tulip.install_c_process('crush', """
    int i = 0;
    while (i < frames * chans) {
        buf[i] = (buf[i] >> 18) << 18;
        i = i + 1;
    }
""")
tulip.c_process('crush', True)
```

## 例: ヘビーなディストーション（エフェクト）

オーバードライブ: 信号を天井に叩きつけます。ドライブゲインを掛け、±1.0 にクランプし、古典的な 3 次のサチュレータ（`y = x - x³/3`）で角を丸めることで、ブザーのような音ではなく唸るような音になります。ニーの上限が 2/3 になるので、3/2 倍してピークをフルスケールに戻します。

```python
tulip.install_c_process('dist', """
    int drive = 10;                      // 1 = クリーンなブースト、10 = ヘビー
    int i = 0;
    while (i < frames * chans) {
        int s = buf[i] * drive;
        if (s > 8388608) s = 8388608;    // +/-1.0（S8.23）にクランプ
        if (s < -8388608) s = -8388608;
        int y = s - fxmul(fxmul(s, s), s) / 3;
        buf[i] = y + y / 2;
        i = i + 1;
    }
""")
tulip.c_process('dist', True)
```

状態を持たないので static は不要です。`drive` を上げればもっと汚れます。

## 例: CZ-101 のフェイズディストーション（オシレータ）

Casio の CZ シリーズは、フィルタをまったく使わずに明るくフィルタらしい音色を作っていました。ふつうのコサインを*ねじ曲げた*位相で読むのです。1 周期のうち最初の `dcw` の割合の部分でコサインの前半全体を、残りで後半全体を掃引します。`dcw` が小さいと、開いたフィルタのようにザラついて明るくなり、`dcw = 32768` なら純粋なコサインです。位相の管理は Q16（65536 = 1 周期）で、参照時に `<< 7` して `cos_lut` の S8.23 位相に変換します。

```python
tulip.install_c_osc('cz', """
    static int phase[256];               // osc ごとの位相: ポリフォニーがタダで手に入る
    int dcw = 6554;                      // 折れ点（1 周期の 0.1）
    int i = 0;
    while (i < frames) {
        int p = phase[osc];
        int wp = 0;                      // ねじ曲げた位相、Q16
        if (p < dcw) wp = p * 32768 / dcw;
        else wp = 32768 + (p - dcw) * 32768 / (65536 - dcw);
        buf[i] = fxmul(cos_lut(wp << 7), amp);
        p = p + phase_inc_q16;
        if (p >= 65536) p = p - 65536;
        phase[osc] = p;
        i = i + 1;
    }
""")
tulip.c_osc('cz', 200)
amy.send(osc=200, wave=amy.SINE, bp0='10,1,500,0.2,250,0', vel=0)
amy.send(osc=200, note=60, vel=1)
```

インストールのたびに `dcw` を変えて掃引すれば（あるいは本体を拡張して別のカウンタで変調すれば）、CZ のエンベロープに相当する音色変化が作れます。

## 例: バイトビート（オシレータ）

[バイトビート](https://canonical.org/~kragen/bytebeat/)は、整数演算の C の 1 行が*そのまま*楽曲になるジャンルです。サンプルごとにカウンタ `t` を 1 ずつ進め、シフトとマスクで捏ね回し、下位ビットを鳴らします。次は古典的な式を Tulip のオシレータにしたものです。ノートのピッチは無視されます（式そのものがメロディです）が、ベロシティとエンベロープは `amp` 経由でゲートとして効きます。

```python
tulip.install_c_osc('beat', """
    static int t[256];
    int i = 0;
    while (i < frames) {
        int n = t[osc];
        int v = (n * (n >> 12 | n >> 8) & 63 & n >> 4) - 32;
        buf[i] = fxmul(from_int16(v * 1024), amp);
        t[osc] = n + 1;
        i = i + 1;
    }
""")
tulip.c_osc('beat', 200)
amy.send(osc=200, wave=amy.SINE, bp0='10,1,10000,1,500,0', vel=0)
amy.send(osc=200, note=60, vel=1)   # ノートを押さえたまま、展開していく様子を聴いてみましょう
```

この式（`t*(t>>12|t>>8)&63&t>>4`）は 6 ビットの出力を生み、それを中心を戻したうえで `from_int16` でフルレンジにスケールしています。好きなバイトビートに差し替えてください。整数演算子は一式すべて使えます。アイデア: `t` を 1 ではなく `phase_inc_q16` から導いた値で進めて鍵盤で移調できるようにする、あるいは 2 つの式を走らせてミックスする、など。

## ちゃんと動いている？ デバッグ

- `tulip.c_process_calls(name)` は処理したブロック数を数えます。増えていれば、コードは呼ばれています。エフェクトは有効な間、毎ブロック動きます。オシレータはバインドされた osc が鳴っている間だけです。
- コンパイルエラーはインストール時に `ValueError` として送出され、コンパイラのメッセージと、渡した文字列内を指す行番号が付きます。新しいコードがコンパイルできるまで、既存のものは置き換わりません。
- オシレータから音が出ない？ その osc にエンベロープが設定されているか（`bp0=...` の行）、演奏している osc 番号と同じ番号にバインドしたか、`amp` で `fxmul` しているかを確認してください。エンベロープがゼロだと、完璧な無音発生器になります。
- 無音なのに `c_process_calls` は増えている？ 計算がゼロに潰れている可能性が高いです。`int` の除算は切り捨てなので、割る前に掛けましょう。
