## 購入とボードそのものについて

### AMYboard は誰が作っていて、どこで買えますか？

AMYboard はボランティアが運営するオープンソースのプロジェクトです。AMYboard の設計と製造は [Makerfabs](https://www.makerfabs.com/amyboard.html) と協力して行いました。受注と出荷はすべて Makerfabs が担当しています。注文に関する質問は Makerfabs にお問い合わせください。

### 29 ドルの AMYboard には何が付いてきますか？ 組み立てやはんだ付けは必要ですか？

AMYboard の箱には 3 つのものが入っています。
 * 完全に組み立て済みの AMYboard — 3.5mm ジャックを含め、すべての部品がはんだ付け済みです
 * 10HP のモジュラー環境に取り付けるためのアクリル製フロントパネル。任意のディスプレイとノブ用の切り欠きがあります。
 * パネルをボードに固定したい場合に、10 個の 3.5mm ジャックの上から締めるためのナット

 ボードは [Makerfabs](https://amyboard.com/#get) から出荷されます。「組み立て」と言えるのは、ラックに入れたい場合にフェイスプレートをはめてジャックのナットを締めることと、必要に応じてオプションのモジュールを取り付けることくらいです。

### AMYboard の在庫はありますか？

ボードは Makerfabs を通じて販売されており、注文数に応じた「ロット」単位で出荷されます。たとえば AMYboard の発売前に小ロットを製造し、発売時にすぐ売り切れたため、より大きなロットを製造しました。1 ロットの製造には数週間かかります。最新の出荷予定は [Makerfabs の AMYboard ページ](https://www.makerfabs.com/amyboard.html)を確認してください。

### 注文や配送の状況はどう確認しますか？（それと Makerfabs にログインできません！）

注文、決済、配送はすべて [Makerfabs](https://www.makerfabs.com/amyboard.html) が扱っており、私たち（AMYboard のチーム）は注文の照会も変更もできません。注文や配送に関することは次のとおりです。

- **注文と追跡に関する質問:** [Makerfabs の問い合わせページ](https://www.makerfabs.com/contact)をお使いください。返信は早いです。
- **追跡番号:** 注文確認とは**別のメール**で、少し遅れて届くことがよくあります。出荷されていないと判断する前に、受信箱（と迷惑メール）を確認してください。
- **Makerfabs のサイトにログインできない？** 最近ログインが不安定です。ページを完全に読み込ませてから、何度か試してみてください。

### 電源はどうすればよいですか？

3 通りあり、AMYboard は存在する最も高い電圧を使います。**USB-C**（5V）、**Eurorack の 10 ピン**（+12V）、**I2C host / Grove** ポート（3.3V。Tulip などから）です。コンピュータは不要で、普通の USB 電源で十分です。[電源](README.md#power-supplies)を参照してください。

### 音声出力はステレオですか？

はい。ライン入力、ライン出力、S/PDIF のジャックはすべて**ステレオの 3.5mm** コネクタです。音の定位には AMY の `pan` パラメータを使ってください。

### ハードウェアなしで AMYboard を試せますか？

2 通りあります。

- [ウェブエディタ](https://amyboard.com/editor)の **Simulate** モードは、ファームウェア一式（シンセ、スケッチ、OLED、エミュレートされたエンコーダ）をブラウザ内で動かします。
- **AMYboard の VCV Rack プラグイン**は、ファームウェアそのものを Rack のモジュールとして動かします。AMYboard Online の MIDI ポートを、USB の AMYboard ではなく仮想の VCV MIDI エンドポイントに向ければ、スケッチもノブもプリセットもすべて同じように動きます。`.vcvplugin` は [amyboard のリリース](https://github.com/shorepine/tulipcc/releases/tag/amyboard)（Linux/Windows/Mac）から入手し、Rack の plugins フォルダに置いてください。VCV Rack Pro の中でなら、DAW の VST としても動かせます。

### "AMY" は何の略ですか？

AMY はかつて "**A**dditive **M**usic synthesizer librar**Y**"（加算合成の音楽シンセサイザーライブラリ）の略でした。また、出荷されなかった Atari の AMY チップへのオマージュでもあります。初期は加算合成（ブレークポイントを持つサイン波）が中心でしたが、現在のマルチシンセエンジンへと成長しました。とはいえ加算合成の心臓部は[ピアノの音色](https://shorepine.github.io/amy/piano.html)に生きています。

## USB での接続

### AMYboard が "USB JTAG/serial debug unit" としてしか見えません。MIDI もシリアルポートも出てきません。（最も多い質問です）

AMYboard が*ずっと* USB/JTAG デバイスとしてしか現れない場合、**まだ動いていません**。DFU（ファームウェア更新）モードで待機している状態です。確認と対処は次のとおりです。

1. そのポートにシリアルターミナル（`mpremote`、`minicom`、PuTTY、`screen`）で接続します。`waiting for download` のような表示が出れば DFU モードです。
2. **BOOT** を押してファームウェアを起動します。MicroPython の `>>>` プロンプトが出るはずで、その後ボードが USB シリアル（CDC）と USB MIDI のポートを列挙します。
3. ファームウェア書き込み後に DFU を抜けて新しいファームウェアを動かす手順は、**RST の後に BOOT** です。

正常なボードは USB MIDI デバイス（VID `0xCAF0`、PID `0x4009`）と USB シリアルポートとして列挙されます。[USB MIDI が認識されない](troubleshooting.md#usb-midi-not-recognized)を参照してください。

### オンラインエディタ／"Control" が AMYboard を見つけられません

エディタは **WebSerial / WebMIDI** でボードと通信しますが、これらは（デスクトップの）**Chrome か Edge** でしか動きません。Safari と Firefox は対応していないので、ボードはまったく表示されません。また、Connect / Control をクリックする**前に**ボードを接続し、DFU / BOOT の手順を済ませておき、ブラウザが尋ねてきたら正しいポートを選んでください。

**Update firmware** のボタンで「amyboard.com refused to connect」のような表示が出る場合は、ブラウザのキャッシュを消してページを再読み込みしてください。キャッシュに残った古いページがまさにこの症状を引き起こした事例があります。

### Mac/Linux では動くのに Windows では動きません（あるいはその逆）

たいていの環境は macOS、Linux、Windows のいずれでも動きます。特にファームウェアを更新した後はそうです。USB 関連の問題は最近たくさん修正しているので、まずは[最新のファームウェアにアップグレード](firmware.md)してください。片方のマシンでは見えて、もう片方では見えない場合は次を確認してください。

- まず、単に **DFU モード**で止まっていないか確認してください。**BOOT** を押してファームウェアを起動します（上の最初の質問を参照）。
- 確実に**データ対応**の USB-C ケーブルを試してください。多くのケーブルは充電専用でデータを通しません。
- **他に何もポートを掴んでいない**ことを確認してください（`mpremote`、シリアルターミナル、Python の REPL、DAW を閉じます）。
- **Windows** では、デバイスマネージャーの**サウンド、ビデオ、およびゲーム コントローラー**に "AMYboard" があるか確認します。
- **Linux** では、ユーザーを `dialout` グループに追加してから `screen /dev/ttyACM0 115200` などを試します。

特定のマシンでまだ解決しませんか？ **[Discord](https://discord.gg/TzBFkUb8pG) の `#amyboard` チャンネルで質問してください。** 最も早く助けが得られますし、その報告が残っているエッジケースを見つける助けにもなります。

<a id="can-i-plug-a-usb-midi-keyboard-straight-into-the-amyboard-usb-host"></a>
### USB MIDI キーボードを AMYboard に直接挿せますか？（USB ホスト）

いいえ。AMYboard は **USB のデバイス／ガジェットモード専用**です。コンピュータからは MIDI デバイスとして見えますが、挿された USB コントローラを**ホストすることはできません**。（Tulip は USB ホストができますが、AMYboard のハードウェアはできません。）コンピュータなしでキーボードから鳴らすには、**TRS/DIN の MIDI in** ジャックを使うか、あいだに小さな **USB ホスト → TRS MIDI のブリッジ**を挟んでください。RP2040/RP2350 のボードで自作できます（実際に作ったコミュニティメンバーがいます）し、[CME H2MIDI Pro](https://www.amazon.com/dp/B0DQYD3L7D)（約 49 ドル）のような既製品を買うこともできます。

### コンピュータから AMYboard のローカルファイルシステムにファイルをコピーするには？

大きなファイルなら、コンピュータで SD カードに書き込んで、それを物理的に AMYboard へ移すのが便利です（[ストレージ](#storage)を参照）。ファイルが 1〜2 個なら `mpremote` が使えます。たとえば `mpremote resume fs cp local.wav :remote.wav` です。

## ディスプレイ（OLED）

### どのディスプレイに対応していますか？

私たちのファームウェアは標準で **SH1107** と **SSD1327** の OLED をサポートしています。Adafruit の 128×128 モノクロ OLED（[#4741](https://www.adafruit.com/product/4741)）は SSD1327 で、よく動きます。デフォルトでは起動時に AMY のバージョン番号が表示されるので、配線が正しいことがすぐ分かります。

**Adafruit のディスプレイが在庫切れの場合**でも、**SH1107 の 128×128** OLED なら動きます。コミュニティのメンバーが **Pimoroni** や **Mouser** から同じパネルを調達しています。Adafruit 以外のものは JST/STEMMA のソケットではなく 4 ピンのむき出しヘッダが付いていることが多いので、**Dupont から Grove/STEMMA への変換**ケーブルが必要になります（JST 対 JST なのは Adafruit の部品だけです）。

### SSD1306 やノーブランドの OLED が光りません

- **SSD1306** はファームウェアでサポートしていません（ドライバが異なります）が、MicroPython のドライバをボードに置いて自分で使うことはできます。たとえば [micropython-ssd1306](https://github.com/stlehmann/micropython-ssd1306/blob/master/ssd1306.py) です。`/user/current/` にコピーし、スケッチから `import` してください。
- **ノーブランドの OLED** は別のドライバチップや I2C アドレスを使っていることがあります。`amyboard.py` は推測を試みますが、`ssd1327_oled` / `sh1107_oled` のデフォルトアドレスを編集するか、そのチップ用のドライバを用意する必要があるかもしれません。

### ディスプレイを取り付けたら割れた／表示されなくなりました

ディスプレイをフェイスプレートにボルト留めするときは細心の注意を払ってください。手で締めるだけでもガラスがパネルに押し付けられて割れることがあります。ガラスに力がかからないよう、**スペーサーやスタンドオフ**（ナットを重ねるだけでも十分です）を使ってください。私たちも何人かこれで痛い目に遭っています。取り付け穴は **M2** ネジ用です。安価な M2 ネジのアソートに、ナイロンのスペーサーとワッシャーを足すとうまくいきます。4 か所すべてではなく**対角の 2 か所だけ**を使うと、多少の余裕が生まれます。

### OLED の表示が 90° 回転しています

一部のパネル（特にノーブランドのもの）は横向きで立ち上がります。SH1107 ならスケッチで直せます。

```python
amyboard.set_display_rotation(90)   # または 180 / 270
```

この呼び出しは `def loop(tick):` の行より**上**であればどこに置いてもかまいません。それより上はすべて起動時に一度だけ実行されます。回転が効くのは SH1107 パネルだけです（SSD1327 とウェブシミュレータでは無害な no-op です）。

### OLED ディスプレイを 2 台同時に接続できますか？

理屈のうえでは可能ですが、組み込みの `amyboard.display` クラスは最初に見つけたディスプレイを選ぶので、2 台目は自前の MicroPython ドライバで動かす必要があり、2 つのパネルは異なる I2C アドレスにジャンパ設定する必要があります。間違いなく上級者向けのプロジェクトです。

### OLED に文字が出ない、あるいは自作の画面が上書きされます

- これらの OLED では、テキストの色に **1**（255 ではなく）を使ってください。
- きつい `while` ループからディスプレイを更新したり、頻繁に更新しすぎたりしないでください。I2C の帯域がやがて**オーディオを枯渇させ、ボードをクラッシュさせることがあります**。スケッチの `loop()` の中で 1 回につき 1 つずつ更新してください。正しいパターンは `preset_selector`、`house_generator`、`acid_generator` の例を参照してください。
- デフォルトの画面に戻ってしまう場合は、自分のディスプレイ設定のどこかが実行されていません。まずは動作確認済みの OLED サンプルを試してみてください。

## ノブ、エンコーダ、I2C アクセサリ

### どのノブ／エンコーダが使えて、どう接続しますか？

フロントパネルの **I2C（Grove）**ポートで[アクセサリ](accessories.md)を駆動します。よく使われるのは、Adafruit のシングル Seesaw ロータリーエンコーダ、**クアッドロータリーエンコーダ（[#5752](https://www.adafruit.com/product/5752)）**、各種の M5Stack ユニットです。Adafruit の Stemma QT 部品を接続するには次が必要です。

- AMYboard のフロントパネルから最初のアクセサリまでの **Grove から Stemma QT** ケーブル（[Adafruit #4528](https://www.adafruit.com/product/4528)）
- 次のアクセサリをデイジーチェーンする **Stemma から Stemma QT** ケーブル（例: ノブ → ディスプレイ）

アクセサリには**フロントパネル**の I2C ポートを使ってください。背面の "tulip"/host ポートではありません。背面の I2C コネクタは、AMYboard 自体を*アクセサリとして*動かす（デイジーチェーンしたり、Tulip などのホストから駆動したり）ためのもので、背面の HOST ヘッダのピンはファームウェア開発中のシリアルデバッグ用です。どちらもディスプレイやエンコーダとは通信しません。

### フロントパネルのポートはどのコネクタ／ケーブルを使いますか？

**2.0 mm** ピッチの **Grove / MABEE 形式**の 4 ピンコネクタ（HY2.0 / DL20005 とも呼ばれます）で、**STEMMA QT ではありません**。STEMMA QT はより小さい 1.0 mm の JST-SH です。素の STEMMA QT ケーブルは直接挿さらないので、**Grove から STEMMA QT** への変換ケーブル（[Adafruit #4528](https://www.adafruit.com/product/4528)）を使ってください。これらの部品向けの MicroPython ドライバはたいてい「そのまま動き」ます。ドライバの `.py` を `/user/current/` にコピーして `import` してください。

### 複数の I2C アクセサリを分岐／デイジーチェーンするには？

クアッドエンコーダには Stemma QT のジャックが 2 つあるので、そこを通してチェーンできます。スター型のハブが欲しければ、M5Stack が[小型の I2C ハブ](https://shop.m5stack.com/products/mini-hub-module)を売っています。アドレスが衝突しないかぎり、1 組の SDA/SCL に多数のアクセサリをぶら下げられます。

### どのエンコーダでも使える API はありますか？（Adafruit のシングル／クアッド、M5Stack の 8-Encoder）

あります。2026-06-30 のファームウェア以降、`amyboard.encoder()` が接続されているエンコーダのアクセサリ（あるいはウェブシミュレータのエミュレートされたエンコーダ）を自動検出し、単一の API を提供するので、同じスケッチがどれでも動きます。

```python
enc = amyboard.encoder()   # I2C スキャン（またはウェブシミュレータ）で自動検出
enc.type          # "adafruit_single" | "adafruit_quad" | "m5stack" | "web" | "multi" | None
enc.devices       # 接続中の各デバイスを (type, i2c_address) で
enc.encoders      # 接続中の全デバイス合計のエンコーダ数
enc.read(i)       # 累積位置。0 から始まります
enc.button(i)     # 押している間 True（デバイス間で正規化済み）
enc.led(i, r,g,b) # エンコーダ i の LED を設定。各 0..255
enc.reset(i)      # エンコーダ 1 つをゼロに（i を省略すると全部）
enc.invert(True, i) # エンコーダ i の向きを反転（i を省略すると全部）
enc.switch()      # M5Stack のトグル（他のデバイスでは False）
```

AMYboard World のスケッチジェネレータもこの API を使っているので、生成されるスケッチが特定のエンコーダを前提にすることはなくなりました。ただし、World にある古めのスケッチの多くは*特定の*エンコーダ向けに書かれています。「動いているのに何も起きない」場合は、そのスケッチがプリセット選択にシングルエンコーダを期待しているのに手元には 8 連しかない（あるいはその逆）ということがないか確認してください。

### エンコーダ基板を同時に複数つなげますか？

はい。`amyboard.encoder()` は接続されている**すべて**のエンコーダアクセサリを見つけ、フラットなインデックス空間を持つ 1 つのオブジェクトとして提示します。Adafruit の基板にはアドレスジャンパがあり（シングルは 0x36〜0x3D で最大 8 枚、クアッドは 0x49〜0x50 で最大 8 枚）、たとえば 0x36 と 0x37 のシングルエンコーダ 2 台があれば `enc.encoders == 2` になります。インデックスはまず M5Stack、次にクアッド、最後にシングルの順で、それぞれ I2C アドレスの昇順です。特定の 1 枚だけにバインドしたい場合は、そのアドレスを渡します: `amyboard.encoder(addr=0x37)`（あわせて `type="adafruit_single"` で種類を固定することもできます）。

### エンコーダが逆向きに数えます（反時計回りで増える）。どう直しますか？

ハードウェアのリビジョンによってはデテントの位相が逆で、時計回りに回すとカウントが*減る*ものがあります。`invert=True` を渡してすべてのエンコーダの向きを反転させるか、1 つだけ反転させます。

```python
enc = amyboard.encoder(invert=True)  # すべてのエンコーダを反転
enc.invert(True, 2)                  # ...またはエンコーダ 2 だけ
enc.invert(False)                    # ハードウェア本来の方向に戻す
```

### M5Stack の 8-Angle（ポテンショ 8 個）や 8-Encoder はどう読みますか？

```python
import m58angle
m58angle.get(0)   # 1 個目のポテンショ／エンコーダ
m58angle.get(7)   # 8 個目
```

詳細は[アクセサリのページ](accessories.md)を参照してください。エンコーダには、上記の統一 API である `amyboard.encoder()` を優先してください。

### Adafruit のエンコーダ基板の NeoPixel LED はどう光らせますか？

いちばん簡単なのは、上記の統一エンコーダオブジェクトの `enc.led(i, r, g, b)` です。スケッチから Seesaw の NeoPixel レジスタを直接叩くこともできます: `amyboard.neopixel_init(pin=18, n=4)`、`amyboard.neopixel_set(i, r,g,b)`、`amyboard.neopixel_show()`。

### ESP32 の空き GPIO ピンにボタンや LED を配線できますか？

簡単にはできません。使われていない ESP32-S3 の GPIO はどのヘッダにも引き出されていないので、チップに直接はんだ付けする必要があります。追加のコントロールやライトには、上記の I2C アクセサリを使ってください。

### エンコーダの読み取りやディスプレイの更新は `loop()` と `tulip.defer()` のどちらで行うべきですか？

どちらでも動きます。`tulip.defer()` は `loop()` と同じシーケンサを使い、次回呼び出しまでの遅延を指定できるだけです。多くの人にとっては `loop()` がいちばん簡単です。32 分音符ごと、つまり 1 拍あたり 8 回（1 小節あたり 32 回）走るので、タイミングはテンポに応じてスケールします。正確なレートは [`loop()` はどのくらいの頻度で呼ばれますか？](#how-often-is-loop-called)を参照してください。システムが追いつけるよう、**1 回の呼び出しにつき 1 つだけ**読み取り／更新し、自前の重いループは避けてください。

<a id="how-often-is-loop-called"></a>
### `loop()` はどのくらいの頻度で呼ばれますか？

AMY シーケンサの 32 分音符ごとなので、レートはテンポに応じて変わります。

**`loop()` の間隔（ms）= 7500 / テンポ**

| テンポ | 間隔 |
|---|---|
| 60 | 125 ms |
| 108（デフォルト） | 69 ms |
| 120 | 62.5 ms |
| 240 | 31 ms |

（AMY のシーケンサは 48 PPQ で動作し、32 分音符は 6 ティックです。）

CV 入力のポーリングなど、より速い呼び出しが必要な場合は、シーケンサに自分のコールバックを登録してください。下限は 1 ティック、つまり **1250 / テンポ ms** です（テンポ 60 で 21 ms、テンポ 240 で 5.2 ms）。

```python
import tulip
tag = tulip.seq_add_callback(my_fn, 0, 1)   # fn(tick) をシーケンサのティックごとに
# 停止するには tulip.seq_remove_callback(tag)
```

実用上、速度の上限を決めるのは次の 3 つです。

- `cv_in()` はバックグラウンドのタスクがオーディオブロックのレート（約 5.8 ms）で更新しているので、それより速くポーリングしても同じ値を読み直すだけです。
- コールバックは MicroPython のスケジューラ経由でディスパッチされるので、周期に加えてジッタが乗ります。
- `loop()` が 1 周期より長くかかると、重なった呼び出しはキューに積まれるのではなく**スキップ**されます。遅い `loop()` は自分のレートを黙って半分にします。`cv_out()` はブロッキングの I2C 書き込みなので、ただではありません。

CV 入力をシンセのパラメータに連続的にマップしたいだけなら、ポーリングループは使わず、C の中でオーディオレートで動く AMY の CtrlCoef を使ってください。[モジュラーシンセのセットアップ](modular.md#example-cv-input-controls-amy-filter-with-ctrlcoefs)を参照してください。

## スケッチと作業内容の保存

### `sketch.py` を編集しても、再起動するとデフォルトに戻ります

AMYboard は**自己修復**を試みます。起動時に `sketch.py` が致命的にクラッシュすると、デフォルトのスケッチを復元します。したがって元に戻るのは、たいていスケッチがエラーになったということです。最近のファームウェアと[ウェブエディタ](online.md)は、黙って戻す代わりに**スケッチのエラー**（トレースバックと行番号付き）を表示するようになったので、手がかりがなくて困っているならアップグレードしてください。電源投入中に **BOOT** を押し続けるとスケッチをスキップできます（このときハードウェアの自己診断も走ります）。その後で修正するか削除してください。実行中のスケッチは `/user/current/sketch.py` にあります。[ボードが起動しない／クラッシュする](troubleshooting.md#board-wont-boot--crashes-on-startup)を参照してください。

### スケッチの書き込みが変なエラー（`RuntimeError: name too long` など）で失敗し続けます

ボードが妙な状態になったとき（スケッチが変なエラーで書き込めない、デフォルトのスケッチで「syntax error」が出たまま、ドラムのサンプルが見当たらない）の万能の対処は、ファームウェアアップデータから **"Full erase and re-flash"**（クイックアップグレードではなく、遅いほうの選択肢）を実行し、**RST** を押してブラウザを再読み込みすることです。これでサンプルバンクを含むファイルシステム全体が書き直され、Discord で見たこの手の症例はすべて解消しました。

### 以前はエディタがスケッチを自動同期していたのに、今は「read」と「write」を求められます。何が変わったのですか？

ユーザーからのフィードバックに基づき、従来の双方向「sync」を明示的なワークフローに置き換えました。今は **"Read from AMYboard"** か **"Write to AMYboard"** をエディタに指示します。エディタはページ読み込み時にボードを自動で読まなくなり、エディタ内のスケッチを置き換える前に警告し、あなたのスケッチのコードは指示するまでブラウザ内に留まり、AMYboard World からダウンロードしたスケッチはエディタに読み込まれるだけです。書き込むまでボードには何も触れません。同じスケッチのまま Simulate と Control のモードを行き来することもできます。

### スケッチはエラーなく読み込まれるのに動作がおかしいです。どうデバッグしますか？

エディタはスケッチの**インポート／書き込み**時のエラーは報告しますが、後から**実行時**に起きるエラーは（意図的に）報告しません。それを見るには、**シミュレータ**でスケッチを実行し、そこで **Terminal REPL** を開いてください。実行時のトレースバックがターミナルに直接表示されます。（1 つ注意点として、ハードウェア専用の呼び出しの一部はシミュレータに存在しないので、デバッグ中はコメントアウトが必要な場合があります。）

### 自作の Python モジュールやドライバはどこに置きますか？

ボードの `/user/current/` にコピーし、スケッチから `import` してください。実行時に見つかります。**ファームウェアの再ビルド／書き込みが必要なのは C の変更だけ**です。純粋な Python のモジュール（ディスプレイのドライバ、ヘルパー）はリビルド不要です。

### 組み込みモジュール（`m5_8encoder` など）にパッチを当てられますか？

組み込みモジュールは**ファームウェアにフリーズ**されているので、ボード上で編集できません。また `/user/current/` に同名のファイルを置いてもフリーズされたコピーを覆い隠せません。代わりに、モジュールを**別の名前**（たとえば `my_m5_8encoder.py`）で `/user/current/` にコピーし、`import my_m5_8encoder` してください。本当のバグを直した場合は、ぜひ [tulipcc リポジトリの私たちのコピー](https://github.com/shorepine/tulipcc/tree/main/tulip/shared/py)に PR を出してください。ファームウェアのリリースはおよそ週次なので、修正はすぐ届きます。

### MIDI チャンネルと CC の割り当ては電源を切っても残りますか？

はい。[ウェブエディタ](online.md)で **"Write to AMYboard"** をクリックすれば、ノブ／CC の割り当てとパッチがフラッシュに保存され、起動時に復元されます。

### 最後のパッチを覚えていますか？ プリセットとパッチの違いは何ですか？

- 復元されるのは**最後に*保存した*状態**（AMYboard に書き込んだもの）であり、必ずしも最後に演奏した状態ではありません。
- **プログラムチェンジ（PC）**メッセージは内蔵プリセット（Juno 128 + DX7 128）をライブで切り替えますが、フラッシュには**書き込みません**。再起動すると保存した設定に戻ります。
- ウェブエディタでの**「プリセット」**は内蔵の 256 個のシンセプリセットのいずれかで、読み込むと現在のノブ設定を上書きします。**「パッチ」**はチャンネルのノブ設定一式です。恒久化するには "Write to AMYboard" してください。
- PC はプリセット全体を読み直すので、それ以降に加えた**ライブの CC 変更もすべて消えます**。シーケンサがパターンのループごとに先頭で PC を送っていると、CC の変更が毎回リセットされます。PC は曲やパターンの開始時に**一度だけ**送るようにしてください。

## シンセの操作

### ハードウェアのノブをパラメータに割り当てる（MIDI CC）には？

いちばん簡単なのは、[ウェブエディタ](online.md)でパラメータの**ラベル**（ノブ自体ではなく "Freq" などの文字）をクリックし、CC 番号を設定する方法です。以降は、ボードを単体で動かしているときも含めて「そのまま動き」ます。コードからは AMY の `ic` コマンドで CC のマッピングを設定できます（[AMY の API ドキュメント](https://github.com/shorepine/amy/blob/main/docs/api.md#synths-and-voices)を参照）。そのマッピングはスケッチの中に残ります。Juno 風のデフォルト CC マップ（CC 74 → フィルタカットオフなど）も同梱しています。

知っておくとよいことが 2 つあります。

- CC のマッピングは **MIDI チャンネルごと**です。チャンネル 4 に設定したマッピングはチャンネル 5 には適用されません。
- ウェブ GUI で設定した内容はすべて、**スケッチ末尾の設定ブロック**に `ic` の行として書き出されます（例: `i10ic86,...` はチャンネル 10、CC 86）。したがって、チャンネルごとにマッピングをクリックし直すのではなく、1 チャンネルを設定してそのブロックを見て、他のチャンネル用に行をコピー・編集するとよいでしょう。

### ボードをブラウザにつなぎっぱなしにせずにハードウェアコントローラを使うには？

CC の割り当てを一度設定してから、単体運用に移ります。

1. MIDI コントローラを USB でコンピュータに接続し、ウェブエディタの MIDI 入力として選びます。
2. 画面上のノブを動かして、マッピングを確認します。
3. **Write to AMYboard** を実行します。
4. コントローラの MIDI ケーブルを AMYboard の MIDI in に挿し替え、コンピュータを外します。ノブはハードウェア上で動き続けます。

### TRS の MIDI 機材が反応しません。Type A と Type B のどちらでしょう？

**MIDI in** については気にする必要はありません。AMYboard のハードウェアは本質的に TRS の Type A と Type B の両方を受け付けます。**MIDI out** のデフォルトは **Type A** です。下流の機材が Type B なら、実行時に切り替えてください（2026 年 6 月下旬以降の新しいファームウェアが必要です）。

```python
import amyboard
amyboard.set_midi_type('B')   # MIDI OUT を Type B に切り替え
print(amyboard.midi_type())   # -> 現在有効な 'A' か 'B'
```

これは保持されず、再起動すると Type A に戻るので、スケッチの中に呼び出しを入れておいてください。

### MIDI 機材を MIDI in に挿すと、音声出力から電源ハムが聞こえます

これは**グラウンドループ**であり、ボードの故障ではありません。現行の AMYboard は TRS の MIDI in ジャックのスリーブをグラウンドに接続しており、ほとんどの MIDI 機器は（MIDI 規格の指示どおり）MIDI out 側でケーブルシールドをグラウンドに落としています。音声や電源でも 2 台がつながっていると、ハム電流（60 Hz / 120 Hz、50 Hz 圏では 50/100 Hz）がシールドを巡ってオーディオに入り込みます。

対処は **MIDI ケーブル側でグラウンドを切る**ことです。MIDI のデータはグラウンドをまったく使わないカレントループに乗るので、他には何も影響しません。グラウンドリフトの TRS アダプタやケーブル（スリーブ未接続）を使うか、DIN ケーブルの片端でシールドを切ってください。今後のボードリビジョンでは MIDI in のスリーブをハードウェア的にリフトします（[issue #1198](https://github.com/shorepine/tulipcc/issues/1198)）。

### 複数の MIDI 入力（と電源）を同時につないでも大丈夫ですか？

はい。TRS MIDI、USB MIDI、複数の電源（USB + Eurorack）をすべて同時につないで問題ありません。すべての MIDI 入力からのノートが処理されます。ただし USB ポートは**デバイスモード専用**であることを忘れないでください。USB MIDI 接続はコンピュータ（あるいは USB ホスト）に対しては機能しますが、AMYboard に挿したコントローラからは機能しません（[USB ホスト](#can-i-plug-a-usb-midi-keyboard-straight-into-the-amyboard-usb-host)を参照）。

### ドラムの音はどう鳴らしますか？

いちばん簡単なのは、現行ファームウェアではデフォルトで **MIDI チャンネル 10 が GM ドラムキット**になっているので、チャンネル 10 で GM のドラムノート番号（36 = キック、38 = スネア、42 = クローズドハイハット、46 = オープンハイハット、49 = クラッシュ…）を鳴らすことです。スケッチでは、シンセに **GM ドラムキットのパッチ（384〜390: TR-808、TR-909、Linn 9000、MR-12、Tokyo Synthetics、80s Power Kit、Percussion）**を設定します。ノートからサンプルへの対応はパッチの中にあるので、これなしでは素のノート番号でドラム音は鳴りません。

```python
amy.send(synth=10, patch=384)
```

ドラムキットは**シングルボイス**です。1 つのボイスがドラム音ごとに専用の osc 一式を保持するので、`num_voices` はデフォルトの 1 のままにしてください。あとはスケッチから `amy.send(synth=10, note=36, vel=1)` で、あるいは MIDI からトリガします。アップグレード後にドラムの音がおかしい、あるいは鳴らない場合は、**フル消去して再書き込み**してください。クイックアップグレードではサンプルバンクは書き直されません。

### 個々のドラム音を編集できますか？

はい。チャンネルにドラムキットが読み込まれていると、[ウェブエディタ](online.md)は Juno 風のノブを**ドラムごとのパラメータノブ**に切り替えます。各ドラム音のあらゆるパラメータ（ピッチ、レベル、ディケイ…）を編集でき、**MIDI CC にマップ可能**です（ノブのタイトルをクリックして CC を割り当てます。ドラムにはデフォルトの CC はありません）。チャンネルストリップの **Level** スライダー / CC 7 がキット全体の音量を制御します。**Load Preset** のドロップダウンで任意のキットを任意のチャンネルに置いたり、チャンネル 10 を通常のシンセに戻したりできます。私たちの[ドラムシンセのデモ](https://shorepine.github.io/amy/gamma9001/)によく似たものが、自分のハードウェア上で使える形です。

### マスターボリュームの MIDI CC はありますか？

組み込みではありません。CC 7 はチャンネルごとのレベルです。ボード全体のボリュームノブが欲しい場合は、好きな CC を待ち受けて `amy.send(volume=x)` を呼ぶ MIDI コールバックをスケッチに追加してください（スケッチジェネレータが喜んで書いてくれます）。各バスもエディタの Effects パネルに自分の Master Level ノブを持っており、CC にマップできます。

### AMYboard から他の機材に MIDI クロックを送れますか（マスターになれますか）？

はい。スケッチの先頭に次を書いてください（2026 年 7 月中旬以降のファームウェアが必要です）。

```python
import tulip
tulip.external_midi_sync(send=True)
```

これで AMYboard は、AMY シーケンサのテンポで MIDI クロック（F8）とスタート／ストップ（FA/FC）をハードウェアレベルで生成して送出します。Python のタイマーコールバックよりはるかに正確です。（`send=True` を付けない場合、同じ呼び出しは AMYboard を外部クロックに*追従*させます。）

### SysEx で AMY を直接制御できますか？

はい。0〜127 の CC 値よりも表現力があります。`0xF0 0x00 0x03 0x45`（SysEx の開始と私たちのベンダー ID）を送り、続けて **ASCII** の AMY メッセージ、最後に `0xF7` を送ります。**1 文字 1 バイト**なので、AMY のコマンド `i1v0F20`（シンセ 1、osc 0、フィルタ周波数 → 20）は次のようになります。

```
0xF0 0x00 0x03 0x45  0x69 0x31 0x76 0x30 0x46 0x32 0x30  0xF7
```

これにより `424.12456` のような正確な値を送れます。0〜127 のノブ値で十分なら、MIDI CC のサポートを使ってください。

### AMYboard はマルチティンバーですか？ 複数の MIDI チャンネルで別々のパッチを同時に鳴らせますか？

はい。**16 の MIDI チャンネル**それぞれに別のシンセ／パッチを置け、**すべてが同時に有効**です。ウェブエディタは一度に 1 チャンネルしか*表示*しませんが、残りも自分のチャンネルで反応し続けます。制約になるのは RAM とオシレータの総数（AMY は約 250 osc で上限）、そしてパッチが豪華になるにつれての CPU なので、非常に密なマルチティンバー構成では 16 チャンネルすべてを重くする前にボイスが尽きます。（ピッチベンドは現在チャンネル横断でグローバルです。AMY の [#684](https://github.com/shorepine/amy/issues/684) を参照。）

## AMY での音作り

### パッチにピッチや フィルタの LFO を追加するには？

LFO はボイス内の単なるオシレータです。標準的なアナログパッチ（たとえば `patch=6`）は、すでに osc 1 を LFO として設定しています。シンセ 1 のピッチとフィルタを変調するには次のようにします。

```python
amy.send(synth=1, osc=2, mod_source=1, freq={'mod': 0.1})         # ±0.1 オクターブのピッチ LFO
amy.send(synth=1, osc=0, mod_source=1, filter_freq={'mod': 0.5})  # フィルタカットオフの LFO（VCF は osc 0 にあります）
```

LFO を複数使いたい場合は、十分な `oscs_per_voice` を持つボイスをゼロから組む必要があります。

### FM のパッチはどう作りますか？ DX7 のプリセットを編集できますか？

今なら簡単な方法があります。[ウェブエディタ](online.md)で任意の **DX7 プリセット**をチャンネルに読み込むと、完全な **FM 編集画面**が現れます。オペレータごとのタブにライブのエンベロープ表示があり、アルゴリズム、フィードバック、LFO のコントロールもすべて MIDI CC にマップできます。（「アルゴリズム」を CC に割り当ててライブで演奏してみてください。挑戦です。）同梱の DX7 プリセットはすべて 6 オペレータですが、より少ないオペレータでパッチを組むこともできます（`woodpiano` を参照）。

コードで扱う場合、AMY が行うのは **Yamaha 流のフェイズモジュレーション**で、**SINE** のオペレータでのみ機能します（Prophet 風の「アナログ FM」はロードマップにあります。AMY の issue [#474](https://github.com/shorepine/amy/issues/474)）。2 オペレータのボイスには **3 つの osc** が必要です。`ALGO` の osc はオペレータの osc とは別でなければなりません。動く例としては [xanadu.py](https://github.com/shorepine/tulipcc/blob/main/tulip/fs/tulip/ex/xanadu.py) の `fm_note_patch` を参照してください。

### 外部の音声を AMYboard に通せますか／エフェクターとして使えますか？

はい。[ウェブエディタ](https://amyboard.com/editor)で **`audiopassthru`** のスケッチを読み込み、音声入力を有効にすれば、入ってくる信号に内蔵のエコーやエフェクトをかけられます。なお、エコー／ディレイは**すべてのオシレータの合計**に対して適用されます。現状、任意の信号ルーティングはできません。

### ピンポンディレイやマルチタップディレイは作れますか？

厳密にはできません。エコーはルーティング可能なオーディオグラフではないためです。ただしマルチバスのサポート（AMY の [#686](https://github.com/shorepine/amy/issues/686)）が入りました。最大 **4 つのバス、それぞれ独立したエコー／FX** を動かし、シンセを割り当てられるので（上のバスの質問を参照）、「音ごとに別のディレイ」は実現できます。本当のピンポン／マルチタップのルーティングは、やはり自分で DSP を書くことになります（下記）。

### AMY の出力に自分の DSP エフェクトをかけるには？

Arduino のスケッチでは、`loop()` の中で `amy_simple_fill_buffer()` を呼んで完成したサンプルの `int16*` バッファを取得し、それを加工して自分で I2S に送ります。（`amy_external_render_hook` はオシレータのバッファを*生成*するためのもので、最終ミックスの後処理用ではありません。）[Arduino のセットアップ](arduino.md)を参照してください。

AMYboard 自体では、（新しく、まだかなりアルファな）[特定の種類のエフェクトとオシレータ向けのオンボード C コンパイラ](https://github.com/shorepine/tulipcc/blob/main/docs/user_c_dsp.md)が使えます。

### プリセットによっては音が割れたり歪んだりします

だいたい次の順で確認してください。

- **ファームウェアをアップグレードしてください。** ユーザーからの報告を受け、2026 年 7 月初旬に音が大きすぎた Juno プリセット約 30 個の音量を正規化しました。（DX7 のプリセット 2 つ、158 "DX7 TRAIN" と 230 "DX7 SYN-CLAV 3" は既知の不具合があり、大きな雑音を出すことがあります。）
- **ヘッドルーム。** コントローラやシーケンサからの高いベロシティ、あるいはチャンネルごとの高い出力音量はクリップします。シンセの出力音量を **2.5〜3.5** あたりにするとヘッドルームに余裕ができます。
- **ボイスが多すぎる。** 同時発音が多くて AMY が CPU を使い切ると出力が劣化します。次の質問を参照してください。`num_voices` を減らすか、パッチを簡素化してください。
- **ラインレベル。** ボード背面の DIP スイッチがライン出力の振幅を決めます。ミキサーの入力を飽和させているなら確認してください。ケーブルを動かすと変化するようなノイズやパチパチ音は、たいていボードより下流の RF が原因で、ライン出力にグラウンドループアイソレータを入れると直ります。

### ボードが悲しげな下降音を鳴らして止まります。あれは何ですか？

**CPU 過負荷のフェイルセーフ**（2026 年 7 月のファームウェア）です。スケッチが AMY のエンジンを過負荷にすると、パチパチ鳴って固まり手動 RST が必要になる代わりに、ボードが一時停止して小さな下降音を鳴らします。ウェブエディタに接続していればメッセージも表示されます。スケッチを直してやり直すだけで、再書き込みは不要です。

おおまかな**ボイスの予算**で考えてください。Juno のボイスは CPU の約 12%、DX7 のボイスは約 8%、PCM／ドラムのノートは約 2% です。OLED への書き込みや Python の計算にも時間がかかります。実際には Juno なら同時 8 ボイス程度、DX7 なら 12 程度、あるいはその混合です。悲しげな音が出たら、`num_voices` やポリフォニーを減らしてください。上級者向け: `amy.set_render_load_threshold()` でトリガ点を調整できます。

### 2 つ目のシンセチャンネルを設定したら、1 つ目のシンセの音が変わってしまいました

（Juno をモデルにした）アナログのシンセパッチは、音作りにコーラスと EQ の FX を使っており、デフォルトではすべてのチャンネルが 1 組の FX を共有します。ですからチャンネル 1 に、有名な Juno のコーラスを使う Juno のパッチ A11（Brass set 1）を設定し、その後チャンネル 2 に切り替えてコーラスを使わないパッチ A13（Trumpet）を設定すると、チャンネル 1 のコーラスもオフになってしまい、とても薄い音になります。

解決策は**バス**です。AMY はシンセを別々のミックスバス（0〜3）に置け、それぞれが独立した FX を持ちます。[ウェブエディタ](online.md)では、チャンネルストリップの **Bus** プルダウンでチャンネルを専用のバスに移せます。すると Effects の列がそのバスの FX を表示・編集するようになり、各バスが自分の Master Level ノブを持ちます。ドライなドラムを 1 つのバスに、コーラスのかかった広がりのあるシンセを別のバスに、といった具合です。コードでは次のようになります。
```python
amy.send(synth=1, num_voices=6, patch=0, bus=0)  # シンセ 1、バス 0 に Brass set 1 を設定
amy.send(synth=2, num_voices=6, patch=2, bus=1)  # シンセ 2、バス 1 に Trumpet を設定
amy.send(volume='1,1')  # 出力ミックスでバス 0 と 1 のゲインを 1.0 に設定
```

## 複数の AMYboard を連結する

### AMYboard を 2 台以上デイジーチェーンできますか？

できます。音声は **S/PDIF** の in→out で、制御は **I2C** か **MIDI** で共有します。

**I2C の場合** — AMYboard 2 の "tulip"（host）ポートを AMYboard 1 のフロントパネル I2C に接続し、AMYboard 1 で次を実行します。

```python
from machine import I2C
i2c = I2C(0, freq=400000)
amy.override_send = lambda x: i2c.writeto(0x3f, x)
```

**MIDI の場合** — AMYboard 1 の MIDI out → AMYboard 2 の MIDI in とつなぎ、AMYboard 1 で次を実行します。

```python
import amy, midi
amy.override_send = midi.sysex_amy
```

ポリチェーンやボイスの分割のための組み込み機能はありませんが、自分で `override_send` を書いてボード間にノートを振り分けることはできます。

`amy.override_send = None` にすると AMY をローカルのボードに戻せます。オーバーライドが設定されている間は、`amy.load_sample()` / `amy.transfer_file()` のチャンクを含め、すべてが向こう側のボードに送られます。つまりサンプルはローカルではなく向こうに載ります。

### I2C のチェーンで何台まで給電できますか？

おおむね **4 台**が安全な目安で、さらに 1〜2 台いけるかもしれません。各ボードは 3V3_IN のラインから約 350 mA を引き、チェーンを下るにつれて各ボードの電源 FET で電圧が下がります（4 台目で約 2.94 V を測定しましたが、問題なく動きました）。数台を超えて連結する場合は、それぞれに別の電源を与えてください。

## CV とモジュラー連携

### Eurorack の環境なしで（USB 給電などで）CV を使えますか？

はい。CV は普通の USB 電源を含め、**どの電源**でも動きます。電圧を **CV1 か CV2 の IN** にパッチするだけです。TS のパッチケーブルでは**チップが電圧**を、**スリーブがグラウンド**を担います。入力はボードの給電方法に関係なく **−10 V〜+10 V** を測定します。

### CV をゲート入力とピッチ入力として使うには？

[モジュラーシンセのセットアップ](modular.md#cv-triggering)の **「CV によるトリガ」**の例を参照してください。1 つ目の CV 入力を**ゲート**（ノートオン／ノートオフ）に、2 つ目を**ピッチ**に設定しています。その `amy.send(...)` の行を、他は手を加えていないスケッチに貼り付けて AMYboard に書き込めば、すぐ動き出します。

### CV／アナログ入力を増やすには？

AMYboard は CV 入力に **ADS1015** の ADC を使っています。I2C で簡単に追加できる選択肢としては、[Adafruit の ADS1115 ブレークアウト](https://www.adafruit.com/product/1085)（はんだ付けが必要）、[NCD のネジ端子付き ADS1115](https://store.ncd.io/product/ads1115-16-bit-4-channel-precision-analog-to-digital-converter-i2c-mini-module/)、1 チャンネルの [M5Stack ADS1110 ユニット](https://docs.m5stack.com/en/unit/Unit-ADC_V1.1)があります。CV/DAC 出力については、GP8413 のユニットを[アクセサリ](accessories.md)で説明しています。

### ±10V の Eurorack 信号を ADC 用にどうスケールしていますか？

抵抗だけです。アナログの 3V3 電源をバイアスに使う分圧回路で、−10〜+10 V を 0〜5 V にマップしています。[回路図](https://github.com/shorepine/tulipcc/blob/main/docs/pcbs/amyboard/amyboard-1.4-sch.png)を参照してください。詳しくは[モジュラーシンセのセットアップ](modular.md)にあります。

## ケースと取り付け

### Eurorack を使わない場合のケースはありますか？

市販のデスクトップケースはまだありませんが、コミュニティが 3D プリント可能なデスクトップケースやスタンドをいくつも共有しています。最新のリンクは Discord を確認してください。安価な Eurorack 電源としては Tiptop の µZeus が人気です。

### 写真で見かけるラベル入りのパネルは何ですか？

ボードに付属するのは、プレーンなレーザーカットのアクリルフェイスプレートです。Discord の写真に写っている**2 色のラベル入りパネル**はカスタムの 3D プリントで、[3mf ファイルはこちら](https://github.com/shorepine/tulipcc/blob/main/docs/pcbs/amyboard/amyboard_front_panel.3mf)にあります。フェイスプレートの有無にかかわらず、動作は同じです。

なお、標準パネルの切り欠きは **Adafruit の SSD1327 OLED と Adafruit のシングルロータリーエンコーダ**に合わせて採寸されています。他のアクセサリ（クアッドエンコーダ、M5Stack の 8 連）は AMYboard で*動き*ますが、これらの穴には物理的に収まらないので、カスタムパネルを検討してください（コミュニティのメンバーが両方向けの DXF/SVG の改変やケースを共有しています）。クリック感のあるエンコーダを押したときにアクリルがたわむ場合は、ケース内で PCB 自体を（取り付け穴にスタンドオフで）支えるとかなり丈夫になります。

### 小さなケースに AMYboard を 2 枚入れるには、どれくらいの幅が必要ですか？

PCB 自体の幅は約 47 mm（10HP 未満）で、**フロントパネル**が 10HP です。ラックに入れると USB-C には何も挿しませんし、隣り合う 2 枚の間には I2C の "tulip" ケーブルも収まります。20HP のケース（4ms Pod など）なら 2 枚入ります。ラック内で USB-C にアクセスしたいなら、その側に少し余分な HP を確保してください。多くの人は L 字型の USB-C パネルマウントケーブル（と外部リセットボタン）をフェイスプレートに追加しています。

### ラックに取り付けた後でもボードをプログラムできますか？

はい。USB は不要です。[ウェブエディタ](online.md)からフロントパネルのジャックへ **TRS MIDI** 経由でスケッチやパッチを送れます。USB-C ポートがケースの中に隠れているときに便利です。ファームウェアもその場で更新でき、各ボードで `amyboard.wifi(ssid, password)` の後に `amyboard.upgrade()` を実行するだけです。USB で書き込むためにラックから 4 枚のボードを引き抜くよりずっと楽です。

## ストレージ

### どの SD カードが使えますか？

素の MicroPython の SD インターフェースです。**FAT32**（ボリューム 2 TB まで、ファイル 4 GB まで）が使えます。カードがマウントされない場合は FAT32 で再フォーマットするか、別のカードを試してください。[SD カードがマウントされない](troubleshooting.md#sd-card-not-mounting)を参照してください。

### 自分のサンプルはどれくらい読み込めますか？ SD ストリーミングが頭打ちになるのはなぜですか？

起動後、`amy.load_sample()` で読み込むサンプル用に空いている SPIRAM が約 **3 MB** あります。44.1kHz モノラルの PCM でおよそ **30 秒**分で、すべてのサンプルで共有されます。（短くループするサンプルなら十分な長さで、あるユーザーはこれで実用的な「ミニ・メロトロン」を作りました。）SD からのストリーミングは 1 ストリーム程度なら動きますが、SD のインターフェースは 1 ビット SPI（理論値で約 1.5 MB/s）なので、ポリフォニーがあるとすぐ足りなくなります。同時に多くのサンプルを鳴らすには、RAM にプリロードする（`memorypcm`）か、ファイルをフラッシュに置いてください。

## ソースからのビルド

### AMYboard 向けのビルドで特別なことは必要ですか？

ESP-IDF のツールをセットアップしたら、`tulip/amyboard` ディレクトリから `idf.py flash` でビルドと書き込みができます。たいていは先にボードを DFU モードにする必要があります（**BOOT** を押しながら **RST** を押して離す）。ファイルシステム全体を書き直すには `idf.py erase-flash` の後に `python amyboard_fs_create.py full` を実行します。詳しい手順は[ファームウェアのページ](firmware.md)にあります。なお、純粋な Python の変更ならビルドはまったく不要で、`/user/current/` にファイルをコピーするだけです。

### AMYboard と通信する独自のコントロールサーフェスやエディタを作れますか？

もちろんです。ウェブエディタがスケッチの転送、ボードの状態の読み取り、Python の実行、再起動に使っている SysEx ベースのコントロール API は [control_api.md](control_api.md) に文書化されています。私たち自身も CI やテストのハーネスに使っています。Python の参照実装と CLI が [`tools/amyboardctl`](https://github.com/shorepine/tulipcc/tree/main/tools/amyboardctl) にあります。AMYboard Online の代替を作るなら、そこから始めてください。

### Arduino と MicroPython のどちらがよいですか？

私たちの **MicroPython** ファームウェアをおすすめします。I2C のアクセサリが「そのまま動き」ますし、ボードにログインして動かしたままリアルタイムにコードを書けます。**Arduino** はよりベアメタルで完全な制御ができますが、アクセサリ用のライブラリは自分で探す必要があります。[Arduino のセットアップ](arduino.md)と [Python を使う](python.md)を参照してください。
