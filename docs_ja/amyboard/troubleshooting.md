# トラブルシューティング

AMYboard でよくある問題の解決策をまとめました。行き詰まったらコミュニティに声をかけてください。喜んでお手伝いします。

## 助けを求める

 - [Discord](https://discord.gg/TzBFkUb8pG) -- コミュニティから最も早く助けを得られる場所
 - [GitHub Issues](https://github.com/shorepine/tulipcc/issues) -- バグ報告と機能要望
 - [Makerfabs への問い合わせ](https://makerfabs.com/contact.html) -- ハードウェアの不良や配送に関する問題

**ご留意ください**: AMYboard はボランティアによって支えられています。できるかぎりお手伝いしますが、気長にお待ちいただき、まずは以下の手順を試してください。

## まずは必ずアップグレード

多くの問題は新しいファームウェアで修正されています。切り分けを始める前に、[最新リリースへ更新](firmware.md)してください。

## 音が出ない

**基本の確認:**
 - USB-C ケーブル、モジュラー電源、I2C 電源のいずれかが接続されていますか？ AMYboard には電源が必要です。
 - ケーブルは（音声入力ではなく）**音声出力**のジャックに差さっていますか？

**スケッチをリセットする**
 - [AMYboard Online](online.md) で AMYboard に接続し、"Reset" タブを使ってください。これで AMYboard がデフォルトのパッチに戻ります。

**シンセを確認する:**
 - [シリアル接続](python.md)して次を試します:
   ```python
   import amy
   amy.send(osc=110, wave=amy.SINE, freq=440, vel=1)
   ```
   440Hz のサイン波が聞こえるはずです。聞こえれば、音声ハードウェアは正常です。

**MIDI を確認する:**
 - AMYboard は MIDI チャンネル 1 に Juno-6 のパッチ #0 が割り当てられた状態で起動します。コントローラがチャンネル 1 で送信しているか確認してください。
 - 別の MIDI ケーブルやコントローラを試してください。
 - USB MIDI と TRS MIDI のどちらを使っているか、接続が正しいか確認してください。




## シリアル接続ができない / mpremote がボードを見つけられない

 - 別の USB-C ケーブルを試してください。充電専用でデータを通さないケーブルもあります。
 - **CH340K のドライバをインストールする**: OS によっては USB-シリアルのドライバが必要です。[CH340K のドライバはこちらからダウンロード](https://www.wch-ic.com/downloads/CH341SER_ZIP.html)できます。
 - macOS では、**システム情報 > USB** でボードが見えているか確認してください。
 - Linux では `ls /dev/ttyACM*` か `ls /dev/ttyUSB*` を確認します。
 - Windows ではデバイスマネージャーで COM ポートを確認します。
 - 他のプログラム（シリアルモニタ、DAW）がポートを使っていないことを確認してください。

## 書き込めない / ファームウェアアップグレーダが接続できない

シリアルポートを使えるプログラムは同時に **1 つだけ**です。書き込む前に、他に開いているものがないことを確認してください。他のプログラムがポートを掴んでいることが、**Search for AMYboard** が接続できない最もよくある原因です。

 - **Arduino IDE を閉じます**（少なくとも**シリアルモニタ**は閉じます）。ポートを開いたままにして書き込みを妨げます。
 - ボードに接続している **`mpremote` のセッションを終了**し、Python の REPL やシリアルターミナルも閉じます。
 - そのポートの **`screen` セッションを終了**します。`Ctrl-A` の後に `K` で終了できます。
 - ポートを掴んだ **DAW** も書き込みを妨げるので、閉じてください。
 - 迷ったら AMYboard を抜き差ししてから、もう一度 **Search for AMYboard** をクリックしてください。

<a id="usb-midi-not-recognized"></a>
## USB MIDI が認識されない

正常な AMYboard は、USB の **MIDI** デバイスと USB **シリアル**（CDC）ポートという **2 つ**のものとして同時に列挙されます。USB VID は `0xCAF0`、PID は `0x4009` です。*"USB JTAG/serial debug unit"*（VID `0x303A`）しか見えない場合、ボードはまだファームウェアを起動しておらず、DFU モードのままです。**BOOT** を押して実行させてください（書き込み後の手順は **RST** の後に **BOOT** です）。そうすれば MIDI + シリアルとして立ち上がります。

 - 書き込み後に **RST** を押しましたか？ まずそれを試し、次に **BOOT** を押してください。
 - **データ対応**の USB-C ケーブルを使ってください。多くのケーブルは充電専用でデータを通しません。
 - **他に何もポートを掴んでいない**ことを確認してください。`mpremote`、シリアルターミナル、Python の REPL、ポートを掴んだ DAW を閉じます。接続を持てるプログラムは同時に 1 つだけです。
 - **macOS** では **Audio MIDI 設定**を開き、AMYboard が現れているか確認します。
 - **Windows** ではデバイスマネージャーの**サウンド、ビデオ、およびゲーム コントローラー**を確認します。
 - **Linux** では `aplaymidi -l` / `amidi -l` と `lsusb` を確認します。`303a:...` ではなく `caf0:4009` が見えるはずです。

USB 関連の問題は最近たくさん修正しているので、まずは[最新のファームウェアにアップグレード](firmware.md)してください。**それでも USB の問題が続く場合は、[Discord](https://discord.gg/TzBFkUb8pG) の `#amyboard` チャンネルで質問してください。** 最も早く助けが得られますし、残っているエッジケースを見つける助けにもなります。

## AMYboard Online の問題

### Web MIDI が動かない
 - Web MIDI には（デスクトップの）**Chrome か Edge** が必要です。Firefox と Safari は Web MIDI に対応していません。
 - amyboard.com を開く前に MIDI デバイスを接続しておいてください。
 - MIDI デバイスのセレクタをクリックして、自分のデバイスを選んでください。
 - システムによっては、MIDI アクセスの許可を与える必要があります。

### 「Could not connect to AMYboard」/ 「Pull from AMYboard」のポップアップが繰り返し出る

 - シリアル接続（mpremote、ターミナル、Python の REPL）で AMYboard に**接続していない**ことを確認してください。切断してからやり直します。
 - amyboard.com の**サイトデータを消去**してブラウザを再起動します。DevTools → **Application → Storage → Clear site data**（またはアドレスバーのサイト設定メニュー）です。古い保存状態が、Pull のポップアップがループするよくある原因です。
 - 他の環境（DAW、MIDIKeys、[ウェブの MIDI テスター](https://controllertest.io/midi-tester)）ではボードが MIDI に反応するのにエディタから Pull できない場合は、**もう一度 Pull を試してください**。ボードの再起動が終わっていれば、2 回目で成功することがよくあります。
 - ブラウザの **JS コンソール**に診断メッセージが出ていないか見てください。
 - それでも解決しない場合は[ファームウェアを再書き込み](firmware.md)してください。

## MIDI の問題

### MIDI のタイプが違う（Type A と Type B）
 - AMYboard のデフォルトは Type A の MIDI です。機材が Type B を使う場合は次のようにします:
   ```python
   import amyboard
   amyboard.set_midi_type('B')
   ```
 - 恒久的に設定するには、これを `sketch.py` に追加してください。

### TRS の MIDI 入力を接続すると音声出力にハムが乗る

 - **MIDI 入力**にシンセやコントローラを挿した瞬間に現れる電源ハム（60 Hz / 120 Hz、50 Hz 圏では 50/100 Hz）は**グラウンドループ**です。現行の AMYboard は MIDI 入力ジャックのスリーブをグラウンドに落としており、ほとんどの MIDI 機器は（MIDI 規格どおり）MIDI 出力側でケーブルシールドをグラウンドに落としています。2 台の間に音声や電源の接続があると、ループが閉じます。
 - **MIDI ケーブル側でグラウンドを切る**ことで解消できます。MIDI はカレントループでデータ伝送にグラウンドを使わないので、これは無害です:
   - **グラウンドリフトの TRS アダプタまたはケーブル**（スリーブ未接続）を使う、または
   - DIN の MIDI ケーブルの片端でシールドを切る。
 - 今後のボードリビジョンでは、MIDI 入力のスリーブをハードウェア的にリフトする予定です。[issue #1198](https://github.com/shorepine/tulipcc/issues/1198) を参照してください。

<a id="cv-out-voltages-are-wrong-v15-boards"></a>
## CV 出力の電圧がおかしい（v1.5 のボード）

最新の量産分（リビジョン **v1.5**）のボードには、出力レンジが半分の状態で起動する新しいデートコードのロットの GP8413 CV DAC が載っています。その結果、CV 出力の電圧はすべて**半分のスケールで、かつ 5V 低く**なります。`cv_out(0, 0)` はジャックで約 **-5V** となり、0V より上には到達できないため、ピッチ CV は数オクターブ低い音になります。ボードの回路はリビジョン間で同一で、変わったのは DAC チップのロットだけです。v1.4 以前のボードは影響を受けません。

**対処: [ファームウェアをアップグレードしてください](firmware.md)。** 2026 年 8 月以降のファームウェアは、すべてのボードリビジョンで、起動のたびに正しい DAC レンジを選択します。

まだアップグレードできない場合は、CV を出力する前に起動ごとに一度、次を実行してください（`sketch.py` の先頭が適した場所です）。

```python
import amyboard
amyboard.get_i2c().writeto_mem(88, 0x01, bytes([0x11]))
```

これはどのリビジョンでも安全です（すでに正しいレンジで起動する v1.4 世代の DAC では何もしません）が、電源を切ると失われるので、起動のたびに実行する必要があります。

<a id="board-wont-boot--crashes-on-startup"></a>
## ボードが起動しない / 起動時にクラッシュする

 - **セーフモード**: AMYboard の電源投入中に BOOT ボタンを押し続けます。`sketch.py` の実行をスキップし、ハードウェアの自己診断（音声入力、CV 入出力）も行います。すべてのテストに合格するとチャイムが鳴ります。終わると通常の REPL になるので、スケッチを修正または削除できます。
 - `sketch.py` や `boot.py` にバグがある場合は、BOOT を押し続けてスキップし、REPL か `mpremote` で削除してください:
   ```bash
   mpremote resume fs rm :user/current/sketch.py
   ```
 - フラッシュを消去して書き直す「工場出荷リセット」も試せます。[ファームウェアアップグレードのページ](firmware.md)を参照してください。

<a id="sd-card-not-mounting"></a>
## SD カードがマウントされない

 - SD カードが FAT32 でフォーマットされていることを確認してください。
 - 別の SD カードを試してください。互換性の問題があるカードもあります。
 - 手動でマウントします:
   ```python
   import amyboard
   amyboard.mount_sd()
   ```
   エラーメッセージが出ていないか確認してください。

## I2C デバイスが見つからない

 - バスをスキャンして何が接続されているか確認します:
   ```python
   import amyboard
   i2c = amyboard.get_i2c()
   print(i2c.scan())
   ```
 - 想定されるアドレス: `0x40`（PCM9211）、`0x48`（ADS1015 ADC）、`0x58`（GP8413 DAC）、`0x49`（Seesaw エンコーダ）。
 - 配線を確認してください。SDA と SCL が入れ替わっている可能性があります。
 - I2C ラインにプルアップ抵抗があることを確認してください（AMYboard にはオンボードデバイス用に内蔵されています）。
