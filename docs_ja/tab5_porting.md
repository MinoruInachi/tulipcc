# M5Stack Tab5 移植メモ

このリポジトリは現在、ESP32-S3 ボード上の Tulip をサポートしています。M5Stack Tab5 はこれとは異なるターゲットクラスです。ESP32-P4 をベースとし、5 インチ 1280×720 の MIPI-DSI ディスプレイを使用するため、既存の TulipCC ボード定義には収まりません。

## Tulip 移植に関係する Tab5 のスペック

- メインコントローラ: ESP32-P4NRW32、デュアルコア RISC-V、360 MHz
- 無線モジュール: ESP32-C6-MINI-1U
- フラッシュ: 16 MB
- PSRAM: 32 MB オクタル
- ディスプレイ: 5 インチ IPS、1280×720、MIPI-DSI
- タッチ: 新しい個体ではディスプレイ／タッチが統合されたスタック（ST7123 または ST7121）。初期の個体では GT911 が見えることがある
- オーディオ: ES8388 コーデック、ES7210 AEC フロントエンド、デュアルマイク、スピーカー、ヘッドホンジャック
- 拡張: USB ホスト、USB OTG、RS-485、microSD、M5-Bus、HY2.0-4P、GPIO_EXT

## 移植時に引き継ぐ価値のある公開ピンマップ情報

- LCD 電源／バックライト: G22 がディスプレイ側の LEDA を駆動する
- タッチバス: SDA、SCL、TP_INT がタッチコントローラ向けに配線されている
- タッチコントローラのリビジョン: 公開ドキュメントには GT911 0x14 / ST7123 0x55 / ST7121 0x55 が記載されており、2025 年後半に ILI9881C + GT911 の分離構成から統合 ST7123 構成へスクリーンドライバが変更されたと注記されている
- パネルのリセット／電源レール: LCD_RST と TP_RST は PI4IOE5V6408 IO エキスパンダ経由で制御される
- 外部電源: EXT5V_EN が背面 M5-Bus、側面拡張、HY2.0-4P への 5V を切り替える
- 内蔵無線の電源: WLAN_PWR_EN が ESP32-C6 モジュールのレールを制御する
- USB-A 電源: USB5V_EN が USB-A ホスト電源をゲートする
- 電源オフパルス: PWROFF_PLUSE が電源制御に使われる

## 現在の TulipCC に足りていないもの

- Tulip ファームウェアツリーに esp32p4 ビルドターゲットがない
- 現在のボードレイヤに MIPI-DSI パネルの立ち上げコードがない
- ST7123/ST7121 系に対応した Tab5 固有のタッチドライバ統合がない
- 現在の esp32s3 ボード群に Tab5 のボード定義とピンマップがない

## 公式 BSP をベースラインにする

M5Stack が公開している Tab5 向け ESP-IDF BSP は出発点として有用ですが、TulipCC にそのまま流用できるわけではありません。公開されている BSP の依存関係は現在、次のものが中心です。

- ディスプレイ: `espressif/esp_lcd_ili9881c`
- タッチ: `espressif/esp_lcd_touch_gt911`
- UI レイヤ: `espressif/esp_lvgl_port`
- オーディオサポート: `espressif/esp_codec_dev` と `espressif/esp_codec`
- `esp32p4` ターゲット上の ESP-IDF 5.4.x

このベースラインは、統合された ST7123/ST7121 スクリーンスタックを説明している新しい製品ページのドキュメントとも矛盾します。Tulip への移植という観点では、スクリーンリビジョンの検出、またはディスプレイ／タッチの二系統立ち上げが必要になる可能性が高いということです。

## 実務的な移植手順

1. esp32p4 のビルドターゲットとボードディレクトリを追加する。
2. 公式 Tab5 BSP から始め、旧来の ILI9881C/GT911 系と新しい ST7123/ST7121 系を分離する。
3. 1280×720 の MIPI-DSI ディスプレイパイプラインを立ち上げる。
4. 実装されているスクリーンドライバのリビジョンに合わせて Tab5 のタッチ初期化を追加する。
5. Tab5 の回路図から GPIO、オーディオ、ストレージ、電源制御ピンをマップする。
6. 実機上でブート、フレームバッファ、タッチ、USB、オーディオを検証する。

## 具体的な立ち上げ計画

### フェーズ 0: ベースラインの棚卸し

- 手元の Tab5 の正確なリビジョンと、パネルが旧来の ILI9881C/GT911 設計か、新しい ST7123/ST7121 統合リビジョンかを確認する。
- サポートしたいボードリビジョンに対応する、公開 M5Stack BSP のリビジョンを押さえる。
- Tulip が M5Stack BSP を依存として使うのか、必要な LCD／タッチコンポーネントを直接ベンダリングするのかを決める。

### フェーズ 1: ボードの足場づくり

- 現在の esp32s3 ツリーと並ぶ形で、新しい esp32p4 ボードファミリを追加する。
- Tab5 のボード定義、ボード名、MicroPython のボードメタデータを追加する。
- 共通の共有コードとボード固有のソースファイルという、既存の Tulip ボードの分割方針を踏襲する。

### フェーズ 2: ディスプレイパイプライン

- 公式 Tab5 のディスプレイ経路から始め、パネルバックエンドをリビジョンごとに差し替え可能にする。
- 上位のグラフィックス API を書き直さずに DSI パネルを駆動できるよう、ディスプレイスタックを Tulip のフレームバッファロジックから分離しておく。
- 最終的な向き、カラーオーダー、リフレッシュレートが Tulip の既存レンダリング前提と一致することを検証する。

### フェーズ 3: タッチ入力

- 実装されているコントローラのリビジョン向けにタッチの立ち上げを追加する。
- 新しい入力面を作るのではなく、タッチ座標を Tulip の既存タッチ API に流し込む。
- タッチ経路が初期の GT911 ハードウェアと後期の ST7123/ST7121 ハードウェアの双方を許容できるようにする。

### フェーズ 4: 周辺機能と電源

- ES8388 と ES7210 のオーディオ初期化を追加する。
- microSD スロットのストレージ初期化を追加する。
- ディスプレイ、USB ホスト、無線、拡張の電源を安全に有効化できるよう、電源とレール制御の GPIO を配線する。

### フェーズ 5: Tulip への統合

- 現在のボードと同じ順序で REPL、ディスプレイ、タッチが初期化されるよう、ボードを Tulip の起動処理に組み込む。
- 新しいターゲットが現在の esp32s3 ビルドを乱さないよう、Tab5 以外の機能はボード判定の内側に置く。
- ディスプレイ、タッチ、オーディオ、USB、SD カード、電源イベントについて、初回ブート検証チェックリストを用意する。

## 実装を始めたときに触ることになりそうな箇所

- Tulip ハードウェアツリー配下の esp32p4 用の新しいボードディレクトリ
- 現在の esp32s3 の `mpconfigboard.cmake` に相当するボード設定ファイル
- 現在の `mpconfigboard.h` に相当するボードヘッダ
- Tab5 固有のディスプレイおよびタッチのソースファイル
- esp32p4 向けの分岐が必要になる、Tulip 共有のディスプレイ抽象レイヤ
